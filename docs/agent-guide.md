# 에이전트 작업 지침

## 제품과 문서

- 이 저장소는 프레임 단위 탐색·추출, 비파괴 타임라인 편집, 오디오 믹싱 및 내보내기를 제공하는 VS Code 비디오 편집기를 개발한다. 기능 기준은 [요구사항](video-editor-requirements.md), 코덱 후보와 배포 조건은 [코덱 비교](codec-license-comparison.md), 구현 계약은 [상세 설계](detailed-design.md), 작업 순서는 [구현 계획](implementation-plan.md), 검증 추적은 [테스트 체크리스트](test-checklist.md)다.
- 사용자 지시가 이 문서보다 우선한다. 기능, 설계 또는 검증 범위가 바뀌면 관련 문서를 같은 변경에서 갱신한다. 문서는 `docs/`에 작성한다.
- 현재 구현과 테스트 실행 환경은 아직 없다. 존재하지 않는 코드 구조나 명령을 완료된 것처럼 기재하지 않는다. 구현하면서 실제 구조와 실행 명령을 이 문서와 README에 기록한다.
- UI 문구와 명령 이름은 영어, README와 `docs/`는 한국어를 기본으로 한다. VS Code 테마와 키보드 접근성을 고려한다.

## 구현 원칙

- 원본 미디어를 유지하고 프로젝트의 편집 정보와 타임라인 위치를 별도로 관리한다. 원본 시간과 타임라인 시간의 변환, 클립 경계 및 오디오 동기화를 명확히 정의한다.
- 프레임 레이트와 타임스탬프를 정확하게 표현하고 탐색·추출·편집·출력에서 일관된 결과를 보장한다. VFR과 비정수 프레임 레이트는 지원 여부와 동작을 명시하고 검증한다.
- 미디어 처리와 UI를 분리하고 장시간 작업의 진행률, 취소, 실패와 자원 정리를 처리한다. 오래된 탐색 결과가 새 결과를 덮어쓰지 않게 한다.
- Webview에는 제한적인 CSP를 적용하고 메시지 유형, 파일 경로 및 입력 범위를 검증한다. 오류를 조용히 무시하지 않고 사용자 파일과 개인정보를 불필요하게 노출하지 않는다.
- 지원 형식은 실제 디코더·인코더와 배포 구성을 기준으로 명시한다. 확장자만으로 지원을 보장하지 않는다. 필요 없는 다수의 압축 형식은 추가하지 않는다.

## 라이선스와 배포

- 확장과 함께 배포하는 의존성, 코덱, 바이너리, 폰트 및 테스트 자산은 실제 배포 방식에서 재배포 가능한 오픈 라이선스여야 한다. 무료 사용과 재배포 가능은 다르다.
- 패키지 메타데이터뿐 아니라 실제 포함된 구현체, 하위 의존성, 바이너리 버전과 빌드 옵션을 확인한다. 라이선스 호환성, 고지, 소스 제공, 수정·교체 등 적용 의무를 충족한다. 코덱 특허와 소프트웨어 라이선스를 별도로 검토하며 미확인 사항을 기록한다.
- GPL과 LGPL은 해당 조건을 만족할 수 있는 경우 검토할 수 있으나, 프로젝트 라이선스와 배포 형태가 정해지기 전 호환성을 단정하지 않는다. 권리자의 결정 없이 프로젝트 자체 라이선스를 지정하지 않는다.
- 코덱이나 빌드 구성을 바꾸면 [코덱 비교](codec-license-comparison.md), 제3자 고지와 필요한 라이선스·소스 제공 자료를 함께 갱신하고 실제 패키지 내용을 검증한다. 배포 불가능한 FFmpeg `--enable-nonfree` 빌드를 사용하지 않는다.

## 테스트와 E2E

- 기능 추가·변경·버그 수정에는 동작과 경계 조건을 검증하는 자동 테스트 케이스를 작성하거나 갱신하고 실행한다. 실패를 재현하는 테스트를 우선 추가한다.
- 시간 변환, 프레임 경계, 트림·분할·이어붙이기, undo/redo, 오디오 믹싱·음소거·동기화, 인코딩 결과를 단위 또는 통합 테스트로 검증한다. 짧은 클립, 빈 구간, 서로 다른 프레임 레이트, 무음과 클리핑 등 관련 경계를 포함한다.
- 사용자 작업 흐름은 실제 VS Code Extension Development Host에서 실행되는 E2E로 검증한다. 미디어 가져오기 → 프레임 탐색·추출 → 분할·배치 → 오디오 편집 → 저장·재열기 → 내보내기와 결과 재디코딩을 포함한다. 단위 테스트나 모의 UI만으로 E2E를 대체하지 않는다.
- 합성 또는 배포 가능한 라이선스의 작은 픽스처를 사용하고 출처와 예상 결과를 기록한다. 결정적인 프레임 식별과 오디오 신호를 이용해 출력의 길이, 경계, 영상 내용 및 소리를 검증한다. 손실 압축은 명시된 허용 오차를 사용한다.
- 실패·취소, 지원하지 않는 미디어, 원본 누락 및 복구를 검증한다. 환경 문제와 제품 실패를 구분하고 실행하지 못한 테스트는 이유와 함께 보고한다. 자동화할 수 없는 실제 장치·시각 검사는 별도로 기록한다.
- 테스트 명령과 환경은 구현 후 문서화한다. E2E는 격리된 테스트 사용자 데이터와 확장 디렉터리를 사용하고, 테스트 실패 시 로그를 남긴다. 테스트 결과가 없는 항목을 완료로 표시하지 않는다.
- 문서만 변경한 경우 링크·코드 블록과 공백 오류를 확인한다. 구현이 없는 현 단계에서는 테스트 실행을 주장하지 않는다.

## 변경과 Git

- 기존 사용자 변경을 되돌리거나 삭제하지 않는다. 산출물, 테스트 호스트 다운로드 및 의존성 디렉터리는 필요한 경우를 제외하고 커밋하지 않는다.
- 커밋을 요청받으면 한글 Conventional Commits 형식을 사용한다. 예: `feat: 프레임 추출 추가`.
