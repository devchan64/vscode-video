# 단계 1 플랫폼 검증 계획

상태: Windows와 macOS는 실행하지 않았다. Linux x86_64에서 확인된 사항은 [엔진 검증 기록](engine-validation.md)에 있다. 아래 체크 항목은 미실행이며 제품 지원 플랫폼을 확정한 것이 아니다.

## 대상과 기록

| 대상 | 엔진 및 VS Code 검증 | 성능 | 상태 |
| --- | --- | --- | --- |
| Windows x64 / ARM64 | 설치 경로, 실행 권한, 코덱 검사, Extension Host E2E | 동일 조건 및 장시간 측정 | 미실행 |
| macOS Intel / Apple Silicon | 설치 경로, 실행 권한·격리, 코덱 검사, Extension Host E2E | 동일 조건 및 장시간 측정 | 미실행 |
| Linux x86_64 | 시스템 빌드에서 기능·E2E 일부 확인 | 720p 단독 엔진 기준선 | 부분 실행 |
| Linux ARM64 및 기타 | 실행 파일·아키텍처와 패키지별 동일 검증 | 동일 조건 | 미실행 |

실행 시 OS·버전·CPU·메모리·아키텍처, VS Code·Node·FFmpeg/ffprobe 버전, 출처·해시·빌드 옵션, 실행 명령과 결과·로그를 기록한다. 실패나 미설치는 성공으로 표시하지 않는다. 사용자가 설치한 여러 빌드를 대표하는 지원 최소 버전과 조합은 검증 후 정한다.

## 공통 자동 검증

- [ ] 설정한 절대 경로와 PATH 검색, 공백·한글 경로, 미설치·오류 경로, 실행 권한, 도구 버전 불일치를 확인한다.
- [ ] VP9·Opus 인코더/디코더와 WebM 입출력을 확인하고 인코더만 없을 때 입력 가능·출력 불가를 표시한다.
- [ ] `npm run check`, `npm run test:unit`, `npm run test:integration`, `npm run test:e2e`를 실행한다. 셸 스크립트에 의존하는 단위 테스트의 Windows 대체 픽스처를 구현해 실제로 실행한다.
- [ ] 시간 초과, 작업 중 취소·패널 종료 후 하위 프로세스가 남지 않는지, 출력 한도·오류 안내가 올바른지 확인한다.
- [ ] CSP와 신뢰되지 않은 작업 공간에서 실행 파일 설정을 검증하고 명령 인자에 쉘이 관여하지 않는지 확인한다.
- [ ] 생성한 CFR·비정수 FPS·VFR 파일의 probe, 비키프레임 탐색·재디코딩과 원본 보존을 확인한다. 실제 편집 기능이 구현된 후 전체 E2E도 실행한다.

## 플랫폼별 사항

- **Windows:** `.exe` 경로와 PATH/PATHEXT, 공백·유니코드, 파일 잠금과 기존 파일 교체, 작업 취소 시 프로세스 종료를 검증한다. `cmd`/PowerShell 래퍼가 아니라 실제 실행 파일을 기준으로 테스트한다.
- **macOS:** Intel/Apple Silicon 실행 파일과 아키텍처 일치, 사용자 설치 경로, 실행 권한, Gatekeeper·격리 속성과 실행 실패 안내를 확인한다. 운영체제 기본 PATH가 셸과 다를 수 있으므로 VS Code 실행 환경에서 직접 검사한다.
- **Linux:** 배포판별 라이브러리·PATH 차이, 실행 권한과 임시 파일 시스템, 패키지 라이선스와 장시간 처리를 추가 확인한다.

## 성능과 배포

- [ ] `python3 scripts/benchmark-engine.py`의 동일 합성 입력·설정, 워밍업과 반복 횟수를 기록한다. 현재 스크립트의 `resource` RSS는 Unix 기준이므로 Windows는 별도 측정 도구·단위를 명시하고 결과를 혼동하지 않는다.
- [ ] 대표적인 실제 영상, 1080p 이상, 긴 영상·반복 탐색, 동시 작업과 앱 전체 메모리·UI 지연을 측정한다. 목표와 허용 기준을 정한 후 통과 여부를 판정한다.
- [ ] 각 엔진 빌드의 출처·라이선스·특허 조건을 확인한다. 사용자가 별도 설치해도 확장 자체의 배포 의무와 특허 검토는 별도다. 프로젝트 라이선스와 최종 배포 승인이 정해지기 전 출시 준비 완료로 표시하지 않는다.
