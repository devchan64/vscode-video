# 외부 미디어 엔진 검증 기록

## 2026-11-16: Linux x86_64

- 대상: 사용자가 설치한 `/usr/bin/ffmpeg`, `/usr/bin/ffprobe`, 모두 `4.4.2-0ubuntu0.22.04.1`. 이 경로는 테스트 환경이며 확장이 바이너리를 포함하거나 특정 시스템 경로에 의존하지 않는다.
- SHA-256: ffmpeg `36d94a605d612e4090d1b8aec889d0c0801c6eafb1593c90f5c0dfd2e2966a45`, ffprobe `d4f3ef9c12be756793cad83dd2004d89f49c1c4094053bfbbe7e28925c8fa4fd`.
- FFmpeg `-version` 설정에는 `--enable-gpl`, `--enable-shared`, `--enable-libvpx`, `--enable-libopus` 및 기타 라이브러리가 포함된다. 시스템 배포판 제공 개발 도구를 사용했고 VSIX에 동봉하지 않는다. 이 빌드를 LGPL 전용 배포 바이너리로 취급하지 않는다. 사용 가능한 실제 빌드와 특허 허여는 각각 검토해야 한다.
- `npm run test:integration`: 임시 디렉터리에 FFmpeg `testsrc2` 영상과 440 Hz 합성 음원으로 1초 WebM 파일을 생성한다. CFR 10 fps, 30000/1001 fps 및 프레임을 제거한 VFR에 대해 VP9 무손실 인코딩과 Opus 인코딩, ffprobe 스트림·프레임 조회, 앞쪽 키프레임 사이 위치의 입력 탐색 후 디코딩 프레임 MD5와 순차 디코딩 프레임 MD5 비교, 전체 재디코딩을 확인했다. 픽스처는 테스트 종료 시 삭제하며 파일을 배포하지 않는다.
- 위 검사는 FFmpeg의 시제품 동작에 한정된다. 편집기의 프레임 추출 구현, 모든 PTS·코덱 경계, 실제 오디오 파형·동기화 품질, 성능 목표와 타 플랫폼을 검증한 것은 아니다. VFR은 생성한 한 사례만 확인했다.
- `npm run test:unit`: 누락된 실행 파일, 권한·종료 오류, 시간 초과, 출력 제한, 취소, 인코더 누락, 도구 버전 불일치 및 공백·한글 경로를 테스트한다. Windows의 가짜 실행 파일 테스트는 제외된다.
- Extension Host E2E는 현재 시스템 FFmpeg의 기능 검사 결과를 Webview에 표시하는 흐름을 확인한다. 미디어 가져오기·편집·출력 E2E는 해당 기능 구현 후 수행한다.

## 남은 작업

- Windows·macOS 및 기타 배포 환경에서 도구 탐색, 프로세스 종료·권한·기능 차이를 검증하고 지원 버전과 성능 목표를 확정한다.
- 실제 프레임·오디오 어댑터, 다양한 PTS·VFR 경계, 필터·프로토콜 및 재생·출력 품질은 단계 3 이후 구현과 함께 검증한다.
- FFmpeg 및 각 라이브러리의 소프트웨어 라이선스, 사용자가 얻은 빌드의 획득·이용 조건과 코덱 특허 허여를 검토한다. 프로젝트 자체 라이선스와 출시 승인은 미결정이다. [코덱 비교](codec-license-comparison.md), [배포와 연동](media-engine-distribution.md) 참고.

## 엔진 단독 성능 측정

2026-11-16 Linux 6.8 x86_64, Intel i7-1165G7, 논리 CPU 8개, 위 FFmpeg 4.4.2에서 `python3 scripts/benchmark-engine.py`를 실행했다. 입력은 `testsrc2` 1280×720/30fps, 3초 영상과 48kHz 합성 음원이다. VP9 `deadline=good`, `cpu-used=4`, `threads=4`, GOP 60, 영상 1Mbps와 Opus를 사용했다. 각 작업은 1회 워밍업 후 3회 측정했으며 시간은 프로세스 시작·종료를 포함한다.

| 작업 | 측정값 (초) | 중앙값 |
| --- | --- | --- |
| 합성 입력 생성 및 인코딩 | 1.830, 1.938, 1.909 | 1.909초 |
| 생성 파일 전체 A/V 디코딩 | 0.093, 0.092, 0.098 | 0.093초 |
| 1.5초 위치에서 영상 1프레임 탐색 | 0.076, 0.074, 0.073 | 0.074초 |
| 스트림 메타데이터 probe | 0.035, 0.035, 0.034 | 0.035초 |

생성 파일은 348,547바이트이며, 종료된 자식 프로세스 중 최대 RSS는 226,232 KiB다. RSS는 전체 실행의 자식 프로세스 최대치로, 개별 작업별 메모리나 동시 프로세스 메모리가 아니다. 해당 환경에서만 3초 콘텐츠 인코딩 중앙값이 약 1.57배 실시간 속도였다. 합성 소스 생성과 디스크 I/O를 포함하며 다른 영상, 코덱 설정, 워크로드나 기기에서 같은 결과를 보장하지 않는다. 3회 측정은 성능 분포를 평가하기에 충분하지 않다. 이 수치는 **엔진 기준선**이며 편집기 재생·UI 지연, 메모리 누수, 긴 영상, 1080p/4K 또는 결과 품질의 성능 기준을 충족한다는 뜻이 아니다. 현재 수치 목표는 정해지지 않았다.

## 라이선스 검토: 이번 빌드

- 배포판 패키지 `ffmpeg 7:4.4.2-0ubuntu0.22.04.1`의 `ffmpeg -L`은 GPL-2.0-or-later를 표시하며, `--enable-gpl` 빌드다. [FFmpeg 공식 설명](https://ffmpeg.org/legal.html)은 선택한 GPL 구성 요소에 따라 FFmpeg 전체에 GPL이 적용될 수 있음을 명시한다. 이 테스트 빌드는 사용자 설치 시스템 실행 파일이고 확장에 포함하지 않는다. 별도 프로세스 호출만으로 모든 라이선스 결합 문제나 향후 배포 의무가 해소된다고 단정하지 않는다.
- 같은 시스템의 `libvpx7 1.11.0-2ubuntu2.5` 패키지의 주 라이선스는 BSD-3-Clause이고 추가 구성 요소의 고지는 패키지별로 다르다. [libvpx 라이선스](https://github.com/webmproject/libvpx/blob/main/LICENSE)와 별도 [특허 허여](https://github.com/webmproject/libvpx/blob/main/PATENTS)를 확인한다. `libopus0 1.3.1-0.1build2`의 배포판 고지는 BSD 3조항 조건을 포함하며, [Opus 라이선스와 특허 선언](https://github.com/xiph/opus-website/blob/master/license.md)은 별도로 확인한다. 이 버전 정보는 설치된 패키지 기준이며 모든 동적 의존성의 법적 검토 완료를 뜻하지 않는다.
- 현재 시험용 VSIX에는 FFmpeg, 코덱 또는 npm 런타임 의존성이 들어 있지 않다. 포함 항목은 `npm run package`로 재확인한다. 배포할 때는 실제 VSIX와 사용 방식, 별도 배포 여부에 따라 고지·소스 제공 및 결합 효과를 검토해야 한다.
- 제시된 특허 허여는 권리자와 조건의 범위 내에서 검토하며 모든 제3자 특허 주장에 대한 보증이 아니다. 배포 지역·사용 방식이 미정이고 프로젝트 자체 라이선스도 미결정이므로 최종 법적 적합성이나 출시 승인을 주장하지 않는다.

Windows와 macOS에서 실행할 항목과 결과 기록 기준은 [플랫폼 검증 계획](platform-validation.md)을 따른다.
