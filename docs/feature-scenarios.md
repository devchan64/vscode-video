# 사용자 시나리오 검토

상태: 설계 검토 초안. 아래 기대 결과는 요구사항이며 구현·테스트 성공을 뜻하지 않는다. 범위는 로컬 데스크톱 VS Code의 MVP이며, 코드·미디어 엔진과 허용 오차는 아직 검증되지 않았다. [요구사항](video-editor-requirements.md), [상세 설계](detailed-design.md), [테스트 체크리스트](test-checklist.md)를 함께 읽는다.

## FS-001 확장 열기와 외부 엔진 설정

**전제:** 사용자는 데스크톱 VS Code에서 확장을 연다. FFmpeg와 ffprobe는 동봉되지 않을 수 있다.

1. 명령 팔레트에서 편집기를 열고 Preview·Edit 모드를 확인한다.
2. 엔진 경로가 설정되어 있으면 이를 사용하고, 설정이 없으면 PATH에서 탐색한다.
3. 각 실행 파일과 필수 디코더·인코더·컨테이너 등 실제 기능을 검사한다.

**기대:** 빈 화면과 모드 전환은 엔진이 없어도 사용할 수 있다. 미설치·실행 실패·기능 누락의 이유와 설치 또는 설정 방법을 표시하고 누락된 기능에 의존하는 작업만 제한한다. 예를 들어 인코더만 없으면 가져오기·탐색은 허용하고 출력은 제한한다. 잘못 지정한 경로를 다른 바이너리로 조용히 대체하지 않는다. 설정 변경 후 다시 검사한다. 사용자 설치 엔진을 자동 다운로드하거나 VSIX에 동봉했다고 가정하지 않는다.

**검증 연결:** `E2E-000`, `TC-009`. 명시적 경로, 공백·한글 경로, PATH, 권한, 불일치·시간 초과를 포함한다.

## FS-002 프로젝트 생성과 미디어 가져오기

**전제:** 지원 여부가 검증된 엔진과 영상 두 개, 배경 오디오가 있다. 첫 후보는 WebM/VP9/Opus이며 WAV 오디오도 별도 검증한다.

1. 새 프로젝트를 만들고 영상과 오디오를 가져온다.
2. 파일을 probe해 길이, 스트림, 해상도, 프레임 레이트와 오디오 정보를 표시한다.
3. 미디어를 선택해 원본 화면에 표시하고 프로젝트에 저장한다.

**기대:** 성공한 미디어만 목록에 반영한다. 원본은 수정하지 않는다. 손상 파일, 지원하지 않는 형식, 사용자가 파일 선택을 취소한 경우 기존 목록·편집 상태를 보존하고 이유를 안내한다. 사용 가능한 형식은 실제 엔진의 검사와 테스트 결과에 따라 표시한다.

**검증 연결:** `E2E-001`, `TC-010`, `TC-014`.

## FS-003 미리보기와 편집 모드 전환

**전제:** 미디어 또는 타임라인이 열려 있고 재생 위치와 편집 이력이 있다.

1. Edit에서 클립을 선택하고 타임라인을 확대한다.
2. Preview로 전환해 원본 또는 타임라인을 선택하고 탐색한다.
3. 다시 Edit로 전환하고 이전 선택과 이력을 확인한다.

**기대:** 전환 시 재생은 일시정지하며 위치, 선택, 확대·스크롤과 이력은 보존된다. 대상 전환 시에도 재생을 일시정지하며 원본과 타임라인은 각각 마지막 위치를 유지한다. Preview에서 편집 UI는 숨겨지고 Host도 편집 명령을 거부한다. 전환 자체는 프로젝트 revision과 수정 상태를 바꾸지 않는다. 키보드로 전환할 수 있고 현재 모드를 보조 기술에 전달한다. 이전 요청의 늦은 디코딩 결과는 버린다.

**검증 연결:** `E2E-000`, `E2E-007`, `TC-015`.

## FS-004 프레임 탐색과 이미지 추출

**전제:** 영상이 로드되었고 표시할 타임스탬프를 확인할 수 있다.

1. 원본에서 특정 위치를 지정하고 이전·다음 프레임으로 이동한다.
2. 프로젝트 타임라인에서도 프레임 단위로 탐색한다.
3. 표시 중인 프레임을 이미지로 저장한다.

**기대:** 원본은 PTS 순서, 타임라인은 프로젝트 프레임 격자로 이동한다. 키프레임 사이 요청도 정확한 프레임을 표시한다. 연속 탐색 시 마지막 요청만 반영한다. 추출 이미지는 표시 프레임과 일치하며 원본과 프로젝트 파일을 덮어쓰지 않는다. PTS를 신뢰할 수 없는 입력은 임의 프레임을 반환하지 않고 오류를 표시한다. VFR은 검증 후 지원 범위를 공지한다.

**검증 연결:** `TC-001`, `TC-002`, `TC-010`, `TC-011`, `E2E-002`.

## FS-005 영상 자르기와 이어 붙이기

**전제:** 영상 두 개가 프로젝트에 있고 Edit 모드다.

1. 두 영상을 타임라인에 추가하고 첫 클립을 프레임 경계에서 분할·트림한다.
2. 불필요한 부분을 삭제하고 나머지를 순서대로 배치한다.
3. 빈 구간을 리플 삭제하고 undo·redo한다.

**기대:** 원본은 변경되지 않고 시작 포함·끝 제외 구간이 유지된다. 연결된 영상과 오디오는 함께 움직이고 잘린다. 영상 트랙 충돌이나 원본 범위 밖 트림은 거부한다. 리플 삭제는 모든 트랙의 뒤쪽 클립을 같은 길이만큼 당기며, 다른 클립이 대상 구간에 있거나 경계를 가로지르면 데이터 손실 없이 거부한다. undo·redo 후 배치와 연결 관계가 복원된다.

**검증 연결:** `TC-004`, `TC-005`, `E2E-002`, `E2E-004`.

## FS-006 오디오 분리와 믹싱

**전제:** 오디오가 포함된 영상과 배경 오디오가 타임라인에 있다.

1. 영상 오디오를 분리하고 음소거하거나 일부를 삭제한다.
2. 배경음악을 별도 트랙에 배치하고 볼륨과 페이드를 조절한다.
3. 타임라인을 재생하고 출력한다.

**기대:** 분리된 오디오는 독립적으로 이동·트림할 수 있으며 원본은 그대로다. 연결 상태를 유지한 A/V는 원본 시작 오프셋을 보존한다. 여러 트랙은 합산되며 음소거·볼륨·페이드가 미리보기와 출력에 같은 규칙으로 반영된다. 클리핑은 제한하고 경고한다. 오디오 장치가 없으면 안내하고 무음 재생을 선택할 수 있다.

**검증 연결:** `TC-003`, `TC-012`, `E2E-003`, `E2E-005`. 청감과 실제 장치 동기화는 환경을 기록해 별도로 검증한다.

## FS-007 저장, 재열기와 원본 복구

1. 프로젝트를 저장하고 닫은 뒤 다시 연다.
2. 원본 파일을 이동한 상태에서 프로젝트를 열고 재연결한다.
3. 작업 중 비정상 종료가 발생한 경우 복구 후보를 확인한다.

**기대:** 저장된 클립 배치·오디오 설정이 복원된다. 원본 누락·변경 가능성을 알리고 재연결 파일을 다시 검사한다. 잘못된 프로젝트나 미지원 버전은 덮어쓰지 않는다. 저장 실패 시 이전 파일과 수정 상태를 유지한다. 백업 충돌 시 사용자가 복구 대상을 선택한다. 자동 저장·복구는 단계 7의 완료 조건이다.

**검증 연결:** `TC-006`, `E2E-004`. 원본 해시와 이전 저장 파일을 확인한다.

## FS-008 출력과 결과 확인

**전제:** 두 영상과 편집된 오디오가 타임라인에 배치되어 있다.

1. 출력 경로, 해상도·품질 및 오디오 포함 여부를 선택한다.
2. 프로젝트 스냅샷을 WebM/VP9/Opus로 출력하고 진행률을 확인한다.
3. 결과를 다시 디코딩하여 프레임 순서·경계·길이와 오디오를 확인한다.

**기대:** 출력 FPS는 프로젝트 FPS를 따른다. 결과는 미리보기의 시간·믹싱 규칙과 일치하며 손실 압축의 정량 허용 오차 내에 있다. 출력이 진행되는 동안 편집해도 해당 출력은 시작 시점의 스냅샷을 사용한다. 취소·실패 시 기존 출력과 원본을 보존하고 임시 파일을 정리한다. 원본·프로젝트 경로로의 출력은 거부하고 기존 다른 파일의 덮어쓰기는 명시적으로 확인한다.

**검증 연결:** `TC-013`, `TC-014`, `E2E-005`. 출력 형식과 허용 오차는 엔진 검증 후 확정한다.

## FS-009 실패와 작업 중단

**상황:** 디코더 오류, 지원하지 않는 파일, 출력 경로 권한 부족, 작업 취소, VS Code 종료 또는 엔진 종료.

**기대:** 오류와 취소를 구분하고 작업 상태를 해제한다. 이전 프로젝트·원본과 유효한 출력 파일을 유지한다. 하위 프로세스와 임시 자원을 정리하고 가능한 복구 행동을 안내한다. 종료 중 저장·백업의 충돌이나 원자성은 해당 파일 시스템에서 검증된 범위만 보장한다.

**검증 연결:** `TC-006`, `TC-009`, `TC-011`, `TC-014`, `E2E-004`, `E2E-005`.

## 검토 결과와 구현 전 확인 사항

- MVP 전체 흐름은 외부 엔진 검사 → 가져오기 → 모드 전환·탐색 → 영상·오디오 편집 → 저장·재열기 → 출력·재디코딩으로 연결된다. 각 시나리오의 자동 검증과 실제 장치 검증을 구분한다.
- 프로젝트의 초기 FPS·해상도·샘플레이트를 사용자가 정하는 방식과 첫 미디어에서 제안하는 규칙은 미정이다. 서로 다른 FPS·해상도의 파일을 넣을 때 표시와 변환 정책도 엔진 검증 전에 확정한다.
- 타임라인 미리보기의 실제 프레임·오디오 전달 방식, 재생 지연과 끊김 허용 기준은 미정이다. 구현 시 미리보기와 출력 결과의 일치 기준을 수치화한다.
- 모드 전환 시 선택·위치는 보존하지만 재생은 일시정지한다는 정책은 현재 설계안이다. 사용자 경험 검증 결과에 따라 변경할 수 있다.
- 자동 저장 간격과 복구 선택, 원본 재연결 시 불일치 판단, 출력 덮어쓰기·취소의 파일 시스템별 보장 범위는 구현 전 확정하고 테스트한다.
- 손실 압축 출력의 프레임 이미지·오디오 허용 오차, VFR 및 불완전 PTS 지원 범위, 대상 운영체제는 아직 확정되지 않았다. 검증 전에는 지원 또는 완료로 표시하지 않는다.
