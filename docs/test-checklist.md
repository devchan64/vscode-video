# 테스트 및 E2E 체크리스트

상태: 단계 0의 일부만 실행했다. 체크 표시는 실제 실행과 결과 확인 후에만 변경한다. 구현 단계와 계약은 [구현 계획](implementation-plan.md), [상세 설계](detailed-design.md)를 따르며 사용자 흐름은 [시나리오 검토](feature-scenarios.md)를 참고한다.

## 시간과 편집 모델

- [ ] `TC-001` 정수·비정수 FPS에서 프레임과 유리수 시간 변환의 시작 포함·끝 제외 경계를 검증한다.
- [ ] `TC-002` VFR PTS, 키프레임 사이 탐색, 중복·누락 PTS와 지원 불가 판정을 검증한다.
- [ ] `TC-003` A/V 시작 오프셋과 샘플 경계 반올림을 검증한다.
- [ ] `TC-004` 분할·트림·이동·충돌 거부, 연결/분리, 이력과 원본 보존을 검증한다.
- [ ] `TC-005` 빈 구간 및 클립 리플 삭제, 다른 트랙의 교차 클립 거부를 검증한다.
- [ ] `TC-006` 스키마 오류, 버전 불일치, 저장 실패, 재연결 및 복구 시 기존 파일을 보존한다.

## 미디어와 출력

- [ ] `TC-009` 외부 엔진의 설정·PATH 검색, 누락·권한·코덱 오류, 버전 조합, 시간 초과와 취소를 검증한다.

- [ ] `TC-010` 실제 검증 대상 외부 엔진에서 probe와 식별 가능한 프레임 추출을 검증한다.
- [ ] `TC-011` 연속 탐색에서 늦게 도착한 결과를 폐기하고 취소한 작업의 자원을 회수한다.
- [ ] `TC-012` 알려진 신호로 오디오 분리·게인·음소거·페이드·믹싱·클리핑 및 동기화를 검증한다.
- [ ] `TC-013` 재디코딩한 출력의 프레임 순서·경계·길이와 오디오 신호를 정량 허용 오차로 검사한다.
- [ ] `TC-014` 손상 파일, 미지원 코덱, 저장 실패, 출력 취소 및 임시 파일 정리를 검증한다.

- [ ] `TC-016` 독립 오디오의 샘플 격자 편집과 리플 후 유리수 위치를 보존하고, 프레임 격자와 어긋난 샘플레이트에서 출력 경계를 확인한다.
- [ ] `TC-017` 인코더만 없을 때 가져오기·탐색은 허용하고 출력만 제한하며, 여러 파일 가져오기에서 성공·실패를 개별 처리한다.
- [ ] `TC-018` Source와 Timeline 대상 전환 시 재생이 일시정지되고 이전 대상의 늦은 응답은 폐기된다. Timeline 빈 구간 프레임 추출은 검정이며 원본·프로젝트를 덮어쓰지 않는다.
- [ ] `TC-015` Preview에서 편집 명령을 거부하고 모드 전환이 revision·이력을 바꾸지 않는다. 늦은 디코딩 응답은 폐기한다.

## Extension Host E2E

- [x] `E2E-000` 확장을 활성화해 빈 편집기를 열고 키보드로 Preview·Edit를 전환하며 현재 모드의 접근성 상태를 확인한다.

- [ ] `E2E-001` 격리된 VS Code에서 프로젝트를 만들고 미디어를 가져온다.
- [ ] `E2E-002` 프레임을 탐색·추출하고 클립을 분할·이동·트림·리플 삭제한 뒤 undo/redo한다.
- [ ] `E2E-003` 원본 오디오를 분리하거나 음소거하고 배경음악을 믹싱한다.
- [ ] `E2E-004` 저장·재열기, 원본 누락·재연결과 복구를 확인한다.
- [ ] `E2E-005` 실제 엔진으로 내보내고 결과를 재디코딩해 영상·오디오를 확인하며 원본 해시가 유지되는지 확인한다.
- [ ] `E2E-006` 깨끗한 환경에 VSIX를 설치하고 외부 엔진 연동과 패키지에 실제 포함된 구성 요소의 라이선스 자료를 확인한다.

- [ ] `E2E-007` Preview와 Edit를 전환할 때 재생이 일시정지되고 각 대상 위치, 선택과 이력이 보존되며 키보드로 전환할 수 있다.

## UI와 접근성

- [ ] `UI-001` Preview·Edit의 모드와 Source·Timeline 대상을 시각적으로, 보조 기술로 구분한다.
- [ ] `UI-002` 엔진·미디어 없음, 원본 누락, 진행·취소·오류 상태에서 사용 가능한 동작과 이유를 확인한다.
- [ ] `UI-003` 키보드만으로 재생·탐색·클립 편집과 오디오 조절을 수행하고 포커스를 확인한다.
- [ ] `UI-004` 좁은·넓은 화면, 명암·고대비 테마와 실제 스크린 리더에서 가독성과 상태 전달을 확인한다.

## 검증 기록

2026-11-16: 실제 FFmpeg로 VFR 파일 인덱싱과 PNG 프레임 추출을 통합 테스트했다. Extension Host에서 파일 선택 결과를 주입해 정상·손상 파일 혼합 가져오기, 원본 프레임 이동·시간 탐색, 표시 프레임의 PNG 저장과 프로젝트 저장을 검증했다. OS 대화상자의 직접 조작, 썸네일·파형 및 타임라인 미리보기는 미검증·미구현이다.

2026-11-16: 단계 2의 유리수 시간, 연결 A/V 분할·이동·트림·분리, 리플 충돌과 undo/redo 단위 테스트, 로컬 파일 저장·재열기, 누락·변경 탐지 및 probe 대역을 이용한 재연결 통합 테스트를 실행했다. 프로젝트 생성 Extension Host E2E도 실행했다. 이후 실제 ffprobe 재연결과 Extension Host의 저장·재열기·재연결 UI E2E를 실행했다. 파일 선택·확인 대화상자 결과는 테스트에서 주입했으며 OS 대화상자의 직접 조작은 미검증이다.

2026-11-16 Linux x86_64, Node 20.18.1, VS Code 1.143.0: `npm run check`, `npm run test:unit`, 격리된 Extension Host E2E 통과. Chromium 디버깅 입력으로 Tab·Enter·Shift+Tab·Space를 전달해 포커스, 두 모드 전환과 aria-pressed 상태를 확인했다. `npm run package`로 시험용 VSIX의 실행 코드와 의존성 제외 여부를 검사했다. 외부 엔진의 Linux 코덱 시제품 검증과 남은 범위는 [엔진 검증 기록](engine-validation.md)에 기록했다. 출시용 패키지 검증은 아직 없다.

실행 시 테스트 ID, 날짜, 커밋 또는 작업 트리, OS·아키텍처, VS Code 및 엔진 버전·빌드, 명령, 결과·로그, 사용한 픽스처와 허용 오차를 기록한다. 자동 테스트와 실제 장치·화면 수동 검사는 구분한다. 환경 제약으로 실행하지 못한 항목은 미완료로 남기고 사유를 기록한다.
