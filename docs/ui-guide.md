# 비디오 편집기 UI 가이드

상태: 구현 전 설계안. 이 문서는 화면 구성과 상호작용의 기준이며, 실제 UI나 테스트가 완성되었다는 뜻은 아니다. 기능과 처리 규칙은 [요구사항](video-editor-requirements.md), [상세 설계](detailed-design.md), 사용자 흐름은 [시나리오](feature-scenarios.md)를 따른다. 사용자가 보는 UI 문구와 명령은 영어를 기본으로 한다.

## 1. 화면 원칙

- 한 VS Code 편집기 탭에서 **Preview**와 **Edit**를 명확히 전환한다. 영상의 미리보기 대상인 **Source**와 **Timeline** 선택은 모드와 별개다.
- 현재 모드, 대상, 재생 위치, 프로젝트 저장 상태를 알아볼 수 있게 한다. 클립·트랙의 선택, 음소거, 연결 상태는 색상 외에도 텍스트 또는 아이콘으로 구분한다.
- 원본은 유지하며, 저장은 프로젝트를 저장하고 Export는 새 미디어 파일을 만든다는 차이를 안내한다.
- VS Code 테마 색상과 글꼴을 따르고 좁은 창에서도 주요 재생·모드 전환·저장 동작을 사용할 수 있게 한다. 화면 크기를 위한 수치는 실제 구현과 테스트 후 확정한다.

## 2. 공통 구조

```text
┌ Project name · Unsaved ─────────────── [Preview] [Edit] [Save] [Export] ┐
│ 대상: [Source ▼] [Timeline]                            상태 / 안내      │
│                                                                        │
│                         모드별 작업 영역                               │
│                                                                        │
└────────────────────────────────────────────────────────────────────────┘
```

- **상단:** 프로젝트 이름과 수정 상태, 모드 전환, 저장 및 출력 진입점. 저장·출력은 조건이 충족되지 않으면 이유와 함께 비활성화한다.
- **대상 선택:** Source는 선택된 원본, Timeline은 편집된 프로젝트를 표시한다. 원본이 선택되지 않았거나 타임라인이 비어 있으면 해당 빈 상태를 보여준다.
- **상태:** 엔진 검사, 파일 읽기, 디코딩, 출력, 취소 및 오류를 구분한다. 긴 작업에는 진행 상태와 가능한 취소 동작을 표시한다.
- 그림은 정보의 관계를 설명하는 와이어프레임이며 픽셀 단위 배치나 고정 폭을 뜻하지 않는다.

## 3. Preview 모드

```text
┌ [Preview] [Edit] ───────────── [Source: clip.webm ▼] [Timeline] ┐
│                                                                 │
│                      영상 표시 영역                             │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│ [|◀] [◀ frame] [Play / Pause] [frame ▶] [▶|]   00:00:00 / 00:00:00 │
│ ───────────────────────●────────────────────────  [Extract Frame] │
└─────────────────────────────────────────────────────────────────┘
```

- 영상 화면을 우선 배치하고 재생·일시정지, 시작·끝, 이전·다음 프레임, 탐색 위치와 전체 길이를 제공한다. 현재 프레임 번호 또는 시간 정보를 확인할 수 있어야 한다.
- `Extract Frame`은 현재 선택된 대상의 표시 프레임을 이미지로 저장한다. 저장 취소는 오류로 취급하지 않고 원본과 프로젝트 경로로 덮어쓰지 않는다. 디코딩이 완료된 표시 프레임이 없으면 비활성화한다.
- 타임라인 편집 컨트롤을 숨기고 편집 명령도 거부한다. 재생, 탐색, 대상 선택과 저장은 허용한다.
- Source의 프레임 이동은 원본 PTS 순서, Timeline의 이동은 프로젝트 프레임 격자를 따른다. 대상이 바뀌면 각 대상의 마지막 위치를 표시한다.

## 4. Edit 모드

```text
┌ [Preview] [Edit] ───────────────────────────── [Save] [Export] ┐
│ Media                         │ Source / Timeline               │
│ [Import Media]                │ ┌─────────────────────────────┐ │
│ clip-01.webm                 │ │        영상 화면            │ │
│ clip-02.webm                 │ └─────────────────────────────┘ │
│ music                         │ [Play] [◀ frame] [frame ▶]     │
├─────────────────────────────────────────────────────────────────┤
│ [Split] [Delete] [Ripple Delete] [Snap]  [−] Zoom [+]            │
│ 시간 눈금 ────────────────│ 재생 헤드 ───────────────────────── │
│ Video 1   [ clip-01     ][ clip-02        ]                     │
│ Audio 1   [ 원본 오디오 ][ 원본 오디오   ]    [Mute] [Volume]  │
│ Audio 2   [ 배경음악                       ]    [Mute] [Volume]  │
└─────────────────────────────────────────────────────────────────┘
```

- **Media:** 가져온 파일의 이름과 선택 상태를 표시한다. 가져오기 실패는 기존 목록을 유지하고 해당 파일의 오류를 설명한다.
- **영상 화면:** Source 또는 Timeline 선택을 표시하며 재생과 프레임 탐색을 제공한다. 실제 영상과 선택 대상을 혼동하지 않도록 제목을 표시한다.
- **타임라인:** 시간 눈금, 재생 헤드, 단일 영상 트랙과 여러 오디오 트랙을 표시한다. 클립의 이름, 경계, 선택 및 A/V 연결 상태가 보여야 한다. 오디오 파형은 생성 중·실패 상태도 구별한다.
- **편집 도구:** 선택·이동, 트림, 분할, 삭제, 리플 삭제, 스냅, 확대·축소 및 undo/redo를 제공한다. 선택과 작업 조건이 맞지 않을 때 비활성화 이유를 전달한다. 리플 삭제가 다른 클립과 충돌하면 변경하지 않고 이유를 알린다.
- **오디오:** 영상 오디오 분리, 클립·트랙 음소거와 볼륨, 페이드 조절을 제공한다. 클리핑 경고를 표시한다. 실시간 피크 미터는 MVP 이후다.
- 클립의 드래그 조작에 대응하는 키보드 접근 경로를 제공한다. 구체적인 단축키는 VS Code와의 충돌 검토 및 사용성 검증 후 확정한다.

## 5. 모드와 상태 전환

| 동작 | 표시와 상태 |
| --- | --- |
| Preview ↔ Edit | 재생을 일시정지하고 현재 위치를 유지한다. 프로젝트 revision·수정 상태·이력은 바뀌지 않는다. |
| Source ↔ Timeline | 재생을 일시정지하고 각 대상의 마지막 위치를 복원하며 이전 대상의 늦은 결과를 폐기한다. |
| Edit → Preview → Edit | 클립 선택, 타임라인 확대·스크롤과 undo/redo를 보존한다. 이전 디코딩 응답은 폐기한다. |
| 미디어 없음 | 영상 영역에 빈 상태와 `Import Media` 진입점을 표시한다. 실행할 수 없는 재생·편집 컨트롤의 이유를 안내한다. |
| FFmpeg/ffprobe 없음 또는 기능 누락 | 엔진 상태와 설치·경로 설정 방법을 표시한다. 화면 전환은 허용하고 필요한 미디어 작업은 제한한다. |
| 원본 누락 | 누락된 미디어를 식별하고 `Relink`를 제공한다. 다른 프로젝트 데이터는 보존한다. |
| 처리 중 | 작업명과 진행률을 표시하고 취소 가능한 작업은 `Cancel`을 제공한다. 실패·취소·완료를 구분한다. |
| 저장·출력 실패 | 동작 가능한 오류 메시지를 보여주고 기존 프로젝트·원본·유효한 출력은 유지한다. |

모드 전환 시 재생 일시정지는 현재 설계안이다. 출력 중 편집은 출력 시작 시점의 스냅샷을 변경하지 않는다. 출력 대상이 원본·프로젝트와 같으면 거부하고, 다른 기존 파일을 덮어쓸 때는 명시적으로 확인한다.

## 6. 접근성과 입력

- 모든 주요 기능은 마우스 없이 접근할 수 있고 포커스 순서와 현재 포커스가 명확해야 한다. 모드 선택은 선택 상태를 접근성 API에 노출한다.
- 아이콘 버튼에는 동작을 설명하는 접근성 이름과 툴팁을 제공한다. 재생 버튼은 현재 동작에 따라 `Play` 또는 `Pause`로 이름을 갱신한다.
- 타임라인의 재생 위치, 클립 선택·경계, 볼륨과 음소거는 키보드로 조회·변경할 수 있도록 텍스트와 적절한 접근성 역할을 제공한다. 드래그만 가능한 기능을 만들지 않는다.
- 상태·오류는 색상만으로 알리지 않으며 의미 있는 변경을 보조 기술에 알린다. 시간·프레임 이동처럼 자주 바뀌는 값은 과도하게 반복 안내하지 않도록 검증한다.
- VS Code의 명암·고대비 테마와 확대 배율을 확인한다. 단축키는 텍스트 입력·메뉴 포커스와 충돌하지 않게 처리한다.

## 7. 검증 기준

- `E2E-000`, `E2E-007`: 빈 화면, 키보드 모드 전환과 선택 상태, 위치·이력 보존을 Extension Host에서 확인한다.
- `E2E-001`~`E2E-005`: 가져오기, 프레임 탐색, 영상·오디오 편집, 저장·복구, 출력 흐름에서 상태와 오류를 확인한다.
- 자동 검증과 별도로 좁은·넓은 편집기, 명암·고대비 테마, 키보드 전용 조작, 실제 스크린 리더와 오디오 장치의 결과를 환경과 함께 기록한다.
- 실제 미디어를 사용한 화면 캡처에는 사용자 데이터를 포함하지 않고 배포 가능한 합성 픽스처를 사용한다. 테스트와 수동 점검은 [체크리스트](test-checklist.md)에 결과가 있을 때만 완료로 표시한다.

## 8. 미결정 사항

패널 접기·크기 조절, 정확한 키보드 단축키, 숫자 입력과 드래그의 세부 조작, 파형·썸네일 표시 밀도, 좁은 화면의 전환 기준, 미리보기 품질 선택 위치는 시제품과 사용성 검증 후 확정한다. 재생 위치의 시간 코드 표기 형식과 설정 화면의 문구도 구현 시 검증한다.
