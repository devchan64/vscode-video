# 미디어 엔진 배포와 연동 설계

상태: 외부 엔진 검색과 기능 검사를 구현했으며 Linux 시제품 검증을 진행했다. [검증 기록](engine-validation.md)을 참고한다. 코덱을 확장에 직접 동봉하는 것은 필수가 아니다. 배포 가능한 오픈 라이선스 구현체를 사용하고 실제 획득·이용·배포 조건을 확인한다. [코덱 비교](codec-license-comparison.md)와 [상세 설계](detailed-design.md)를 함께 참고한다.

## 권장 방향

MVP는 **사용자가 별도로 설치한 FFmpeg와 ffprobe를 확장 호스트에서 실행하는 방식**을 우선 검증한다. 확장에는 코덱 바이너리를 동봉하거나 백그라운드에서 자동 다운로드하지 않는다. 초기 지원 조합은 WebM/VP9/Opus이며, 실제 실행 파일의 기능을 검사해 사용할 수 있는 범위만 표시한다. 이 방식은 VSIX 크기와 플랫폼별 바이너리 관리 부담을 줄이지만, 사용자의 설치와 환경별 차이를 수반한다.

이는 설계 선택이며 구현·배포 가능성이 확인된 상태는 아니다. 사용자가 설치한 실행 파일을 호출하는 방식이라도 해당 도구의 라이선스·특허·사용 조건을 안내하고, 확장 자체 및 모든 동봉 의존성의 라이선스 의무를 별도로 검토한다. 사용자 설치 방식이 라이선스나 특허 검토를 없애지는 않는다. 설치 경로는 신뢰할 수 있는 공식 배포 경로를 안내하되 특정 제3자 빌드의 재배포 권한을 가정하지 않는다.

## 방식 비교

| 방식 | 장점 | 비용과 조건 | 판단 |
| --- | --- | --- | --- |
| 사용자 설치 엔진 | 플랫폼별 바이너리 동봉 불필요, 오프라인 환경에서도 이미 설치되어 있으면 사용 가능 | 설치 안내, 경로 설정, 버전·코덱 차이와 실행 오류 처리 필요 | MVP 우선 검증 |
| 플랫폼별 VSIX에 동봉 | 설치 후 바로 사용, 버전과 기능을 통제하기 쉬움 | 플랫폼별 빌드·크기·업데이트, 바이너리와 라이선스·소스 제공·교체 의무 검증 필요 | 이후 선택지 |
| 설치 후 별도 다운로드 | 초기 VSIX 크기 감소 | 배포 서버·무결성·업데이트·취소·네트워크, 해당 바이너리의 재배포 조건 필요 | MVP 범위 밖 |
| WebAssembly 코덱 | 네이티브 실행 파일 의존성 감소 가능 | 메모리·성능·Webview 제약, 실제 바이너리와 의존성의 라이선스 및 빌드 검증 필요 | 별도 성능 검증 전 보류 |

VS Code는 플랫폼별 VSIX를 제공하므로 동봉 방식이 필요해지면 대상별 패키지를 별도로 만들 수 있다. [VS Code 배포 문서](https://code.visualstudio.com/api/working-with-extensions/publishing-extension#_platformspecific-extensions)

## 실행 파일 검색과 검사

1. `ffmpeg`와 `ffprobe`의 명시적 설정 경로를 우선 사용한다. 미설정이면 확장 호스트의 PATH에서 각각 찾는다. 설정값 오류 시 임의의 다른 실행 파일로 조용히 대체하지 않는다.
2. 경로와 실행 가능 여부를 확인하고 셸 없이 인자 배열로 `-version`, `-encoders`, `-decoders` 및 필요한 컨테이너·필터 지원을 검사한다. `ffprobe`도 별도로 실행하고 호환되는 조합인지 확인한다. 버전 문자열만으로 기능을 보장하지 않는다.
3. VP9·Opus 디코딩, WebM 입력과 출력 및 실제 선택한 VP9·Opus 인코더가 있는지 확인한다. 편집·오디오 믹싱에 필요한 필터·프로토콜도 확정된 렌더 경로에 따라 검사한다. 설치된 `libvpx-vp9`와 `libopus`가 없는 빌드의 대체 인코더는 검증 전 자동 선택하지 않는다.
4. 검사 결과에는 경로, 버전, 필요한 기능과 누락 항목을 표시한다. 경로 또는 바이너리가 변경되면 결과를 무효화한다. 실제 파일 인코딩·디코딩 실패는 별도로 처리한다.
5. 미설치, 실행 권한 없음, 비호환 조합, 기능 누락을 구분해 설치 안내 또는 설정 변경 경로를 제공한다. 확장은 계속 열 수 있으며 누락된 기능에 의존하는 작업만 비활성화한다. 예를 들어 인코더가 없더라도 디코더와 probe가 정상이라면 가져오기·탐색은 허용하고 출력은 제한한다. 검사와 실행에 시간 제한을 적용하고 취소·종료 시 프로세스를 회수한다.

## 연동 경계

- Extension Host의 미디어 어댑터만 프로세스를 실행한다. Webview는 임의 실행 파일·인자·환경 변수를 전달하지 않는다. 경로와 미디어 요청을 Host에서 검증하고 셸 보간 없이 실행한다.
- probe, 프레임 추출, 파형·썸네일, 렌더링에 공통 작업 인터페이스를 제공한다. stdout·stderr 크기를 제한하고 진행률, 종료 코드, 취소 및 사용자에게 전달할 오류를 관리한다. 신뢰할 수 없는 미디어와 파일명은 인자 배열로 전달한다.
- 파일 URI와 실행 환경을 명확히 구분한다. MVP는 로컬 데스크톱 확장 호스트에서 로컬 파일을 사용한다. 원격 호스트에서는 검색 경로와 프로세스가 원격 측에 속하므로 지원 전 별도 설계와 테스트가 필요하다.
- 기본 설정은 외부 실행 파일을 명시적으로 지정하거나 PATH를 사용하는 방식이다. 작업 공간 설정으로 실행 경로를 바꿀 수 있다면 신뢰되지 않은 작업 공간에서 자동 실행되지 않도록 VS Code의 신뢰 모델과 설정 범위를 적용·검증한다.
- 외부 실행 파일을 통한 probe·출력 결과와 미리보기의 프레임·오디오 계약은 [상세 설계](detailed-design.md)를 따른다. 버전 차이로 계약을 만족하지 못하면 지원하지 않는 구성으로 알린다.

## 검증 및 릴리스 조건

- 명시적 경로와 PATH 검색, 공백·한글 경로, 미설치·권한 오류, 잘못된 버전·누락 코덱·불일치한 `ffprobe`, 시간 초과 및 취소를 자동 테스트한다.
- 실제 엔진 통합 테스트와 격리된 VS Code E2E에서 설치 확인, 가져오기, 프레임 추출, 편집, 출력·재디코딩을 수행한다. 최소 지원 버전과 대상 플랫폼은 테스트 후 확정한다.
- README와 설정 화면에 설치 전제, 공식 출처, 설정 방법, 지원 기능, 라이선스·특허 확인 필요 사항을 기록한다. 진단에 사용자 파일 경로를 불필요하게 노출하지 않는다.
- 동봉 또는 별도 다운로드 방식으로 전환할 경우 플랫폼별 정확한 바이너리·해시·빌드 옵션·의존성·라이선스·대응 소스와 고지를 기록하고, 실제 패키지 설치·라이브러리 교체 등 해당 의무를 검증한다. FFmpeg는 LGPL 구성 체크리스트에서 `--enable-gpl`과 `--enable-nonfree`를 제외하도록 안내한다. [FFmpeg 라이선스 안내](https://ffmpeg.org/legal.html)
