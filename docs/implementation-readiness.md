# 구현 준비 현황

확인일: 2026-11-13. 이 문서는 현재 개발 환경의 확인 결과와 첫 작업의 입력을 기록한다. 구현 및 배포 검증 완료를 의미하지 않는다.

## 현재 상태

- 단계 0의 확장 골격, 패키지 설정, 메시지 단위 테스트와 실제 키보드 입력을 포함한 Extension Host E2E가 있다. 시험용 VSIX의 포함 파일을 검사했다. 프로젝트 라이선스와 출시 대상 플랫폼은 미결정이다.
- 확인한 환경은 Linux x86_64, Node.js 20.18.1, npm 10.8.2, VS Code 1.143.0이다. 다른 운영체제나 VS Code 버전의 지원 여부는 확인하지 않았다.
- 시스템 FFmpeg 4.4.2에서 VP9·Opus 디코더와 `libvpx-vp9`·`libopus` 인코더가 나열된다. 이는 코덱 목록 확인일 뿐 실제 인코딩, 정확도, 성능과 재배포 적합성 검증은 아니다.
- 시스템 FFmpeg는 `--enable-gpl` 및 여러 외부 라이브러리를 포함한다. 개발용 실험에 사용하더라도 LGPL 전용 배포 빌드로 간주하거나 VSIX에 포함하지 않는다. [코덱 비교](codec-license-comparison.md)의 실제 배포 빌드 검토가 필요하다.

## 첫 구현 단위: 단계 0

[구현 계획](implementation-plan.md)의 단계 0부터 수행한다. 확장 골격의 목적은 테스트 가능한 개발 환경을 만드는 것이며, 편집 기능을 완성한 것으로 표시하지 않는다.

1. VS Code 확장 패키지와 진입점을 구성하고 명령 팔레트에서 빈 편집기 Webview를 연다. Preview와 Edit의 전환 구조와 접근 가능한 빈 상태를 마련한다. 프로젝트 생성·열기 명령은 실제 저장 계약이 구현되기 전에는 완료된 기능처럼 표시하지 않는다.
2. 확장 호스트와 Webview의 메시지 경계, CSP, 종료 처리 및 오류 표시를 구성한다. 모드 변경은 UI 상태로 취급하고 Preview에서 편집 메시지를 거부하는 경계를 준비한다. 실행 가능한 실제 구조와 명령을 README와 에이전트 지침에 기록한다.
3. 단위 테스트 실행기와 격리된 Extension Development Host E2E를 구성한다. 확장 활성화 및 명령 실행 후 빈 편집기 표시, 키보드 모드 전환과 접근성 상태를 확인하고 실패 로그를 남긴다. 편집·재생 기능은 실제 구현 단계에서 별도 E2E로 검증한다.
4. 개발·테스트 의존성의 라이선스와 실제 배포 패키지 포함 여부를 확인한다. 잠금 파일과 패키징 제외 규칙을 관리한다. 프로젝트 라이선스는 권리자의 결정 전 임의로 지정하지 않는다.
5. 합성 픽스처의 생성 방식과 예상 결과를 정하고, 미디어 기능 도입 시 라이선스와 재현 방법을 기록한다. 실제 파일을 생성하거나 결과를 검증하기 전 완료로 기록하지 않는다.

완료 조건은 실제 Extension Development Host에서 빈 화면과 키보드 모드 전환 E2E 성공, 메시지 검증 테스트 및 단위 테스트 명령 재현이다. Linux x86_64 / VS Code 1.143.0에서 실제 키보드 이벤트와 접근성 상태를 검증했다. 다른 환경은 아직 검증하지 않았다. 환경 문제로 실행하지 못하면 원인과 미완료 상태를 기록한다.

## 이후 선행 검증

- **엔진:** 검증에 사용하는 후보 바이너리의 버전·해시·빌드 옵션과 라이선스 자료를 기록하고 VP9/Opus 인코딩·디코딩 및 프레임 정확도를 통합 테스트한다. 시스템 FFmpeg 확인과 배포 빌드 승인을 분리한다.
- **대상 환경:** 최초 지원 OS·아키텍처와 VS Code 최소 버전을 선정하고 실제 설치·실행으로 확인한다. 현재 관찰된 환경이 지원 약속은 아니다.
- **미디어 계약:** VFR 및 시작 PTS, 샘플 경계, 출력 허용 오차를 합성 픽스처로 검증한다. 구현에 필요한 미결정 사항은 [상세 설계](detailed-design.md)에 기록한다.
- **릴리스:** 프로젝트 라이선스, 실제 패키지의 의존성·고지·소스 제공 및 코덱 특허 조건을 확인한다. 미확인 상태에서는 배포 준비 완료로 표시하지 않는다.

테스트 결과와 미완료 항목은 [테스트 체크리스트](test-checklist.md)에 기록한다.
